# 0001. 双轨等级与竞技分（Permanent XP + Seasonal Rating）

- 状态：已采纳
- 日期：2026-07-18
- 关联：feature.md §4.1 / §4.2，PRD §4.6 US-509..US-511

## 背景

仅靠累计 XP 排榜会奖励“打得勤”，未必奖励“打得强”；只靠 Elo 又会让新用户感到挫败，违背“提升用户粘性”的初衷。需要在同一运动内同时满足：

1. 长期成长反馈（等级只升不降，避免挫败）。
2. 真实竞技实力映射（Rating 可升可降，作为排行榜主排序键）。
3. 团队赛与单人赛统一以对手平均 Rating 计算。

## 决策

1. **成长 XP**：单项运动内累计，只增不减。等级阈值 `XP_min(L) = 50 × L × (L - 1)`，单场经验按 feature.md §4.1 档位表计算；升级支持一次跨多级。
2. **竞技 Rating**：单项运动内可升降，初始 `1000`。结算采用 Elo：`ΔR = K × (S - E)`，`K` 取 `60 / 40 / 25 / 15`（定位 / <1500 / <2100 / ≥2100）。团队赛用对方锁定阵容平均 Rating。
3. **段位**：纯展示层，由 Rating 区间映射（青铜 0–1099，白银 1100–1399，黄金 1400–1699，铂金 1700–1999，钻石 2000+），不参与结算。
4. **赛季**：12 周滚动。赛季结束保留 XP 与等级永久记录，Rating 按 `1000 + 0.75 × (R - 1000)` 软重置；写入 `competition_seasons`。
5. **定位赛**：前 5 场排位赛显示“定位中”，不入竞技榜 Top 20。`placement_done` 累加，第 5 场结算后正式入榜。
6. **写入通道**：所有 XP / Rating 变更必须经服务端事务，并写入不可变 `experience_ledger`（`idempotency_key = competition_id:user_id`），前端 RLS 禁止直接更新 `user_sport_progress.xp / level / rating`。
7. **角色无关**：任何用户（含 owner / admin）均可参赛和入榜；`role` 变化不影响运动数据。

## 后果

- 数据存储新增 `user_sport_progress`、`experience_ledger`、`competition_seasons`。
- Edge Functions 需要支持纯友谊赛（不写 Rating）与排位赛（写 Rating）的分支；客户端只提交 `kind`，由服务端决定是否调整 Rating。
- 排行榜默认按 Rating 排序，成长榜按 XP 排序，两个榜共享同一份 `experience_ledger` 聚合。
- 引入定位赛状态，UI 需明确显示；季节结算后用户会看到段位变化通知。

## 备选

- 仅用累计 XP：粘性强但竞技榜单会被高频参赛者占据，与目标偏离。
- 仅用 Elo：竞技性强但用户挫败风险高，且功能定位要求“增强粘性”。
- 双轨 + 段位徽章：被采纳。
